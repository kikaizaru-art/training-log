# Training Log アプリ（筋トレMEMO風）

`app/index.html` 単体で動く、トレーニング記録・予定管理の個人用Webアプリ。外部ライブラリ・サーバ不要で、データは端末のブラウザ（localStorage）に保存される。PWA対応（`manifest.webmanifest` + `sw.js`）で、ホーム画面に追加すればネイティブアプリ同様のスタンドアロン表示・オフライン起動ができる。

## 使い方

### 起動

いずれかの方法で `app/index.html` を開くだけ。

- **GitHub Pages（公開中）**: <https://kikaizaru-art.github.io/training-log/app/>
- **ローカル**: ファイルをブラウザで直接開く（`file://` で動作する）
- **スマホ**: 上記URLを開いて「ホーム画面に追加」すると、専用アイコン・全画面表示の本物のアプリとして起動できる（初回表示後はオフラインでも起動可能）

### 初期データ

初回起動時に、この Vault 由来のシードデータが自動投入される。

- ルーティン3種（火: 上半身push / 木: 脚＋体幹 / 土: Pull＋仕上げ）← [routines.md](../routines.md)
- 種目マスタ14種（部位・自重フラグ付き）← [exercises/](../exercises/)
- セッション実績19件（2026-05-05〜2026-06-13）← [sessions/](../sessions/)

PR（ベスト記録）はマスタに持たず、**セッション履歴から常に動的算出**する（マスタとの同期ズレが構造的に起きない）。

## 画面構成

| タブ | 内容 |
|---|---|
| ホーム | 今日のメニュー提示（training day は routine 種目+前回実績+次回アクション提案、休養日は直近セッションの未刺激種目）、今週サマリ、**週間スケジュール編集**、最近のPR |
| カレンダー | 月表示・実施日に**部位別色ドット**（筋トレMEMO風）、日タップで記録参照/その日への記録追加 |
| 記録 | セッション入力。ルーティン選択で種目展開、**前回実績の自動プリセット/前回コピー**、セット単位の重量×回数入力、保存時に**PR自動判定**、体調/気分1-5、ステータス（完了/一部実施/スキップ） |
| 種目 | 部位別の種目マスタ。PR・最終実施日・全履歴、種目の追加/編集/削除 |
| グラフ | 種目別の最大重量・ボリューム推移（自重種目はレップ推移）、週間総ボリューム、**部位別 last trained**（7日以上未刺激は警告色） |

### 週間スケジュール

曜日ごとに実施するルーティン（または休養）をアプリ内で設定できる。

- 入口: ホームの「今週」カード右上の**スケジュール編集**、または 設定 → **週間スケジュールを編集**
- 変更は即保存され、ホームの「今日のメニュー」・週間予定ストリップ・カレンダーの「予定」表示にすぐ反映される
- 同じルーティンを複数の曜日に割り当てることも可能
- 旧データ（スケジュール未保存）は、初回起動時にルーティン定義の曜日（火/木/土）から自動移行される

### ルーティン編集

ルーティンの中身（種目構成・目安値）をアプリ内で調整できる。

- 入口: 設定 → **ルーティンを編集** ／ 週間スケジュール画面下の**ルーティンの中身を編集** ／ ホームの今日のメニューカード右上の**メニュー編集**
- 編集できる項目: ルーティン名・説明・カラー、種目の追加/削除/並べ替え（↑↓）、種目ごとのセット数・回数・重量の目安、**skip可**フラグ（有酸素枠など。「このメニューで記録」時に展開されない）、**or候補**（下記）
- **or枠（どちらかを選択）**: 種目ごとに「＋ or候補」で代替種目を追加できる（例: ケトルベル or エアロバイク、懸垂 or ゴム補助懸垂）。or枠を含むルーティンで「このメニューで記録を始める」と、先に選択モーダルが開き、今日実施する方を選んでから記録画面に展開される（各候補の前回実績も表示）。ホームの今日のメニューやルーティン一覧では「A or B」と表示される
- 種目追加時は前回実績（セット数・最大重量/回数）が初期値としてプリセットされる
- 新しいルーティンの作成・不要なルーティンの削除も可能（削除しても過去のセッション記録は残り、週間スケジュールの割当は「休養」になる）
- ルーティン名を変更すると、過去セッションの参照名も自動で追随する

### アプリの更新（キャッシュ再読込）

GitHub Pages 版をホーム画面に追加して使っていると、更新後も古い画面がキャッシュから表示され続けることがある。

- 設定 → **アプリを最新版に更新（キャッシュ再読込）** で、ブラウザキャッシュ（Cache API / Service Worker 含む）を破棄してキャッシュバスター付きURLで再読み込みする
- 記録データ（localStorage）には触れないので消えない
- 現在のアプリバージョンは設定画面の最下部に表示される（コード内 `APP_VERSION`）

## Vault（既存Markdown運用）との関係

- 既存の `sessions/*.md` 運用と併用できる。アプリのセッション詳細画面に「**Markdownコピー（Vault形式）**」ボタンがあり、frontmatter付きのセッションmdを生成してクリップボードにコピーできる → そのまま `sessions/YYYY-MM-DD_<routine>.md` に貼り付け可能
- 曜日別提示ロジックは [daily-schedule.md](../daily-schedule.md) の §3/§4（休養日=直近セッションの未刺激種目）を実装
- 次回アクション提案は [progression-rules.md](../progression-rules.md) の簡易版（同一条件の連続回数からマイクロロード/ブレイクスルー時期を提示）

## データ管理

- 設定 → **JSONバックアップ保存 / 復元**（機種変更・ブラウザ変更時はこれで移行）
- 設定 → 初期データ（Vaultシード）へのリセット

## カスタマイズ（今後の拡張ポイント）

コードは `index.html` 内にセクションコメント付きで一枚にまとまっている。

- アプリバージョン: `APP_VERSION`（アプリ更新時に上げる。設定画面に表示される）
- ルーティン定義: `SEED_ROUTINES`（`day` は初期スケジュール用。0=日〜6=土。運用中の曜日割当はアプリ内「週間スケジュール」= `db.schedule`、種目構成の調整はアプリ内「ルーティン編集」で変更する）
- 種目マスタ: `SEED_EXERCISES`（`bp`=部位キー, `bw`=自重）
- 部位と色: `BODY_PARTS`
- 次回アクション判定: `nextActionHint()` / `plateauStreak()`
