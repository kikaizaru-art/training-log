# 筋トレ フォーム入力ガイド（日本語フォーム式）

Markdown を保存形式（SSoT）に保ったまま、**タップ・数値入力中心のフォーム操作**で筋トレを記録するための仕組み。筋トレMEMO アプリの「種目を選んで重量×回数を打つ」体験を、Obsidian 上で再現する。

> 設計判断: データは今まで通り `sessions/YYYY-MM-DD_<routine>.md` の Markdown。フォームはあくまで **入力 UI** であり、保存物は人間が読める Markdown のまま。

## 必要なプラグイン（コミュニティプラグイン）

iPhone の Obsidian でも動作する。設定 → コミュニティプラグイン から導入。

| プラグイン | 役割 | 必須度 |
|---|---|---|
| **Meta Bind** | ノート内に数値入力欄・ドロップダウン・トグルを埋め込み、frontmatter に直接書き込む | ★必須（フォームの核） |
| **Templater** | 「今日の日付・曜日・routine」を自動で埋めた新規セッションを生成 | ★推奨（自動入力） |
| **QuickAdd** | ホームのボタン1タップで「今日の routine テンプレ」から新規セッション作成 | ☆任意（時短） |
| **Buttons** | ノート内に保存・複製などのアクションボタンを置く | ☆任意 |

Bases / Properties は Obsidian 標準機能なので追加不要。

## 使い方（基本フロー）

1. 筋トレ実施後、`templates/session-<routine>.md` を開いて**新規ノートとして複製**
   （Templater/QuickAdd を入れていれば「今日のセッション作成」ボタン1タップで日付・曜日入りで生成される）
2. ノート上部の **入力フォーム**（Meta Bind 欄）で体調・気分・状態をタップ選択
3. 各種目の `セットN: __kg × __回` を、前回値が入った状態から**数値だけ上書き**
4. ボリューム行は計算式を直すだけ（`36*11*3 = 1188kg`）
5. `sessions/2026-MM-DD_<routine>.md` の名前で保存

> フォーム欄（Meta Bind）は frontmatter の `condition` / `mood` / `status` / `routine` に直接書き込まれる。セットの重量・回数は本文テキストで編集する（可変長のため）。

## 入力フォームの記法（Meta Bind）

セッションテンプレ上部に以下が埋め込んである。プレビュー/ライブプレビューで入力欄として表示される。

```markdown
体調: `INPUT[number:condition]`  気分: `INPUT[number:mood]`
状態: `INPUT[inlineSelect(option(completed,完了), option(partial,部分), option(skipped,スキップ)):status]`
ルーティン: `INPUT[inlineSelect(option(上半身push), option(脚＋体幹), option(Pull＋仕上げ)):routine]`
```

- `number:condition` → frontmatter の `condition` に数値を書き込む入力欄
- `inlineSelect(...):status` → ドロップダウン選択を `status` に書き込む

## 自動生成（Templater 例）

`templates/session-上半身push.md` の frontmatter で日付・曜日を自動埋めしたい場合、Templater 有効化後に以下を使う（テンプレ内に記載済み）。

```
date: <% tp.date.now("YYYY-MM-DD") %>
created: <% tp.date.now("YYYY-MM-DD") %>
updated: <% tp.date.now("YYYY-MM-DD") %>
```

Templater 未導入時は `YYYY-MM-DD` を手で置換する。

## 設計上の割り切り

- **セット行をフォーム化しない理由**: 種目ごとにセット数が可変（1〜3）で、自重/加重も混在するため、frontmatter 固定フィールド化するとデータが歪む。重量×回数は「前回値プリフィル済みテキストを上書き」が最速かつ Markdown 可読性も保てる。
- 将来、種目別の重量推移グラフ（[[../2026-06-17_開発プラン|開発プラン]] Phase 4）を作る段階で、セット単位の構造化（Dataview インラインフィールド等）を再検討する。
